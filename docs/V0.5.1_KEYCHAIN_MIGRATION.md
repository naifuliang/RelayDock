# RelayDock v0.5.1 Keychain and signing continuity

## Required behavior

- App launch and endpoint selection must never request Keychain secret data.
- An old credential is read only after a user chooses Load, Migrate once, or
  an operation that explicitly requires the key.
- Legacy single-endpoint and v0.5.0 per-endpoint items migrate into one
  `credential-vault.v1` item. The vault is verified before old-item cleanup.
- A denied or failed item remains untouched and migration can be retried.
- The legacy single-endpoint target UUID survives relaunch until migration
  succeeds.

## Installation continuity

- The one-line installer, ZIP, DMG, and in-app updater invoke
  `Install RelayDock.command`.
- The local signing helper proves that the certificate and private key can sign
  a probe binary and persists the certificate-bound designated requirement.
- An unexpected requirement change stops before the existing app is replaced.
- The installed version, code signature, and requirement are verified before
  the backup app is removed.
- Any failure during replacement restores the backup.
- A damaged signing identity is preserved in a private Recovery directory and
  replaced only after separate user confirmation.
- Developer ID builds preserve their vendor signature. The first transition
  from a local identity requires explicit adoption of the exact Team ID and
  bundle identifier, and later updates must match that recorded identity.
- PKG output is unsupported because it bypasses the transactional installer;
  no packaging path may ad-hoc re-sign an installed app.
