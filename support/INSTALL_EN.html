Install RelayDock

RelayDock 0.2.0 · Multiple endpoints and OpenCode integration

Easiest: paste one command

Open Apple's Terminal app, paste this entire line, and press Return:

/usr/bin/curl -fsSL https://raw.githubusercontent.com/naifuliang/RelayDock/main/install.sh | /bin/zsh

Enter y to confirm, then provide your Mac login password. The script downloads the latest release from GitHub, checks its published SHA-256 hash and existing app signature for integrity, installs it, and opens RelayDock. These checks are not a substitute for Apple notarization.

Security scope: The installer does not disable Gatekeeper globally, install a root certificate, or change the system proxy. For this unsigned test build, it removes quarantine only from the installed RelayDock copy and applies a local ad-hoc signature. Its source can be reviewed in RelayDock's public GitHub repository.

Offline fallback: install from this disk image
  1. Keep the RelayDock disk image window open, then open Apple's Terminal app.
  2. Type /bin/zsh in Terminal. Keep the trailing space and do not press Return yet.
  3. Drag Install RelayDock.command from the disk image window into Terminal. Terminal will insert the exact path automatically.
  4. Press Return. At Continue? [y/N], enter y, then provide your Mac login password when requested.
  5. The script verifies the app, installs it in /Applications, applies a local signature, and launches RelayDock.

Offline installation note: Do not double-click the script, and do not run the dragged path by itself. The command must begin with /bin/zsh. It should look similar to:
/bin/zsh "/Volumes/RelayDock 0.2.0/Install RelayDock.command"

Why not double-click?

This personal test build does not yet have an Apple Developer ID or notarization ticket. Double-clicking it triggers Gatekeeper's “cannot verify” warning. The installer applies an ad-hoc signature locally, so you do not need to run codesign yourself. The drag-to-Terminal method also works when macOS mounts the image as RelayDock 0.2.0 2.

Alternatively, dismiss the warning with Done, then use System Settings → Privacy & Security → Security → Open Anyway. Do not disable Gatekeeper globally and do not use spctl --master-disable.

Configure multiple endpoints and OpenCode

  1. Use “+” in the sidebar to add OpenAI Compatible, OpenAI Responses, Azure OpenAI, or Anthropic endpoints.
  2. Add one or more model IDs to each endpoint and save its API key separately.
  3. Quit any running OpenCode.app instance, then choose Configure and launch OpenCode. RelayDock uses an isolated OPENCODE_CONFIG and does not replace your existing global config.
  4. RelayDock checks GitHub Releases once per day. You can also check manually and download the DMG from the Updates card.

Cursor network probe

  1. Open RelayDock and click 启动探测代理 (Start Probe Proxy).
  2. Click 重启 Cursor 并探测 (Restart Cursor and Probe).
  3. Send one test message in Cursor using Anthropic BYOK.
  4. Return to RelayDock and check whether api.anthropic.com appears.

Scope: version 0.2.0 directly supports multiple OpenCode endpoints. Cursor remains a CONNECT destination probe: it does not decrypt HTTPS or redirect Anthropic requests to Sub2API. The UI keeps these capabilities explicitly separate.

Uninstall

Run Uninstall RelayDock.command through /bin/zsh. It removes the app, all endpoints and Keychain API keys, and RelayDock's generated OpenCode configuration. This version does not install a root certificate or change the system proxy.
