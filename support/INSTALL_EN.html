Install RelayDock

RelayDock 0.6.0 · OpenAI Compatible Cursor setup and OpenCode

Easiest: paste one command

Open Apple's Terminal app, paste this entire line, and press Return:

/usr/bin/curl -fsSL https://raw.githubusercontent.com/naifuliang/RelayDock/main/install.sh | /bin/zsh

Enter y to confirm, then provide your Mac login password. The script downloads the latest release from GitHub, checks its published SHA-256 hash and existing app signature for integrity, installs it, and opens RelayDock. These checks are not a substitute for Apple notarization.

Security scope: The app installer does not disable Gatekeeper globally, install a trusted root CA, change the system proxy, or install a TLS interception certificate. For this unsigned test build, it removes quarantine only from the installed RelayDock copy and creates a stable RelayDock-only signing identity in ~/Library/Keychains/RelayDockLocalSigning.keychain-db. The uninstaller also removes certificate material left by older Bridge releases.

Upgrading from an older build: Launch, endpoint switching, model sync, and other ordinary actions never open old ACL-bound Keychain items. When an older vault or per-endpoint item is found, the UI offers Repair Keychain once; macOS may request access only after you choose it. RelayDock commits the v3 vault only after every old key was read and the new vault passed non-interactive verification. Failure leaves the original data untouched. If an old ACL item cannot be deleted silently, an empty verified v3 tombstone prevents it from being imported again after the last active key is removed.

Signature continuity: the one-line script, ZIP, DMG, and in-app updater share one transactional installer. It compares the designated requirement before replacement and verifies version, signature, and requirement afterward; failure restores the previous app. A damaged local signing identity is never rotated silently: repair requires separate confirmation and preserves the old material in a Recovery directory.

Do not replace the app manually: the raw app payload is kept inside hidden .payload, and the DMG no longer offers an Applications drag target. Use the installer so requirement checks and rollback cannot be bypassed.

Offline fallback: install from this disk image
  1. Keep the RelayDock disk image window open, then open Apple's Terminal app.
  2. Type /bin/zsh in Terminal. Keep the trailing space and do not press Return yet.
  3. Drag Install RelayDock.command from the disk image window into Terminal. Terminal will insert the exact path automatically.
  4. Press Return. At Continue? [y/N], enter y, then provide your Mac login password when requested.
  5. The script verifies the app, installs it in /Applications, applies a local signature, and launches RelayDock.

Offline installation note: Do not double-click the script, and do not run the dragged path by itself. The command must begin with /bin/zsh. It should look similar to:
/bin/zsh "/Volumes/RelayDock 0.5.7/Install RelayDock.command"

Why not double-click?

This personal test build does not yet have an Apple Developer ID or notarization ticket. Double-clicking it triggers Gatekeeper's “cannot verify” warning. The installer applies the local signature, so you do not need to run codesign yourself. The drag-to-Terminal method also works when macOS mounts the image with a numeric suffix.

Alternatively, dismiss the warning with Done, then use System Settings → Privacy & Security → Security → Open Anyway. Do not disable Gatekeeper globally and do not use spctl --master-disable.

Configure multiple endpoints and OpenCode

  1. Use a quick-connect preset for OpenAI API, Kimi Code, or Volcengine Ark Coding Plan, or use Add Endpoint in the single Endpoints card for an OpenAI Compatible, OpenAI Responses, Azure OpenAI, or Anthropic endpoint.
  2. Enter that service's API key, then choose Sync Models. RelayDock tests the connection and automatically fetches the model list. Quick connect only fills a compatible protocol and official API base; it does not purchase a plan, sign in to a provider account, or convert a web subscription into API access.
  3. Choose Verify All to send a minimal request to each enabled model. Definitively unsupported models are removed automatically; authentication, rate-limit, network, and server failures stay visible for correction. This may incur a very small amount of API usage.
  4. Azure's retired legacy deployment-URL mode cannot list deployment IDs; add those IDs manually, then use Verify All. Modern Azure v1 endpoints can sync models.
  5. Quit any running OpenCode.app instance, then choose Configure and launch OpenCode. RelayDock uses an isolated OPENCODE_CONFIG and does not replace your existing global config.
  6. RelayDock checks GitHub Releases once per day. The Updates card shows the result and time. When an update exists, Download and Install verifies the digest, mounted app signature and version, opens the installer, then confirms the installed version before restarting RelayDock.

API keys: OpenAI requires an OpenAI Platform API key; ChatGPT Plus/Pro and API usage are separate. Kimi Code requires a dedicated Kimi Code Console key, which is not interchangeable with a Kimi API Platform key. Ark Coding Plan requires its provider-issued Coding Plan API key. The Kimi Code and Ark presets retain their documented recommended model aliases as a fallback when catalog discovery is unavailable; a successful Sync Models uses the returned catalog. RelayDock writes the key to macOS Keychain only when the endpoint is saved.

One-click Cursor setup

  1. Save and verify an OpenAI Compatible endpoint.
  2. In Cursor one-click Sub2API, choose that endpoint and click Configure and open Cursor.
  3. RelayDock writes Cursor's OpenAI key, Override Base URL, and verified model IDs. Cursor's Anthropic cloud path does not support a custom local endpoint; expose those models through non-claude-* OpenAI-compatible aliases instead.
  4. RelayDock reports success only after the Cursor database transaction and encrypted-key migration verify.

Network behavior: RelayDock does not proxy or intercept Cursor traffic. RelayDock's own model tests and GitHub updates honor inherited HTTP_PROXY/HTTPS_PROXY/ALL_PROXY settings or the macOS default HTTP proxy and its exceptions; unsupported SOCKS/PAC modes fail closed rather than silently bypassing the proxy.

Uninstall

Run Uninstall RelayDock.command through /bin/zsh. It removes the app, endpoints and Keychain API keys, generated OpenCode configuration, Cursor rollback files, any certificate material left by older Bridge releases, and the private local signing keychain. RelayDock never installs a root CA or changes the global system proxy.
