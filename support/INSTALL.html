安装 RelayDock

RelayDock 0.5.1 · Keychain 与安装签名连续性修复

最简单：复制一条命令

打开 macOS 自带的“终端”（Terminal），粘贴下面整行命令并按回车：

/usr/bin/curl -fsSL https://raw.githubusercontent.com/naifuliang/RelayDock/main/install.sh | /bin/zsh

输入 y 确认，再按提示输入 Mac 登录密码。脚本会从 GitHub 下载最新版本，使用发布的 SHA-256 与现有 App 签名检查文件完整性，然后安装并启动 RelayDock。这些检查不等同于 Apple 公证。

安全范围：App 安装器不会全局关闭 Gatekeeper、安装受信任根 CA 或修改系统代理。对于当前未公证测试版，它只会移除 RelayDock 安装副本的 quarantine 属性，并创建稳定的 RelayDock 本地签名身份；安装 App 本身不会添加 TLS 信任。以后若为 Cursor 选择 Anthropic Endpoint，RelayDock 才会另行请求 macOS 信任一个 SAN 仅含 api.anthropic.com、CA:FALSE 的叶证书。卸载器会删除两种身份和该信任。

从旧版升级：RelayDock 启动和切换 Endpoint 时不会读取 Keychain 中的秘密，因此不会突然弹出密码框。发现旧版独立 Key 条目时，界面会显示“一次性迁移”；只有你点击后 macOS 才可能要求授权。新版会先把所有获准读取的 Key 写入并验证统一凭据仓库，再清理旧条目。

签名连续性：一键脚本、ZIP、DMG 与应用内更新共用同一个事务安装器。替换旧 App 前会比较 designated requirement，安装后再次验证版本、签名和 requirement；任何失败都会恢复旧 App。损坏的本地签名 identity 不会被静默轮换，修复必须单独确认，原材料会保留在 Recovery 目录。

不要手动覆盖 App：发布包中的原始 App 保存在隐藏的 .payload 内，DMG 不再提供拖到 Applications 的入口。请使用安装脚本，避免绕过签名连续性与回滚检查。

离线备用：从当前磁盘映像安装
  1. 保持 RelayDock 磁盘映像窗口打开，然后打开 macOS 自带的“终端”（Terminal）。
  2. 在终端中输入 /bin/zsh ，注意末尾需要保留一个空格，先不要按回车。
  3. 把磁盘映像窗口里的 Install RelayDock.command 直接拖到终端窗口。终端会自动填入正确路径。
  4. 按回车运行。出现 Continue? [y/N] 后输入 y，并按提示输入 Mac 登录密码。
  5. 脚本会校验 App、安装到 /Applications、执行本地签名并启动。

离线安装注意：不要直接双击脚本，也不要只把脚本拖到终端后运行。命令最前面必须有 /bin/zsh。完整命令看起来类似：
/bin/zsh "/Volumes/RelayDock 0.5.1/Install RelayDock.command"

为什么不能直接双击？

当前个人测试包还没有 Apple Developer ID 与公证票据。直接双击会触发“无法验证是否包含恶意软件”的 Gatekeeper 提示。安装脚本会完成本地签名，用户无需手动运行 codesign。上面的拖拽方式不依赖固定卷名，即使系统给磁盘映像添加数字后缀也能正确运行。

也可以在弹窗中点击“完成”，然后前往“系统设置 → 隐私与安全性 → 安全性”选择“仍要打开”。不要全局关闭 Gatekeeper，也不要使用 spctl --master-disable。

配置多个端点与 OpenCode

  1. 可直接选择 OpenAI API、Kimi Code 或火山方舟 Coding Plan 快速接入，也可以在同一张 Endpoints 配置卡里手动添加 OpenAI Compatible、OpenAI Responses、Azure OpenAI 或 Anthropic 端点。
  2. 填写对应服务的 API Key 后点击“同步模型”，RelayDock 会测试连接并自动获取模型列表。快速接入只会预填兼容协议与官方 API 地址，不会购买套餐、登录服务商账号或把网页会员转换成 API 权限。
  3. 点击“一键验证全部”，RelayDock 会向每个已启用模型发送最小请求；明确不支持的模型会自动移除，鉴权、限流、网络或服务端错误会保留供修正。这可能产生极少量 API 用量。
  4. Azure 已停用旧版 deployment 列表接口，因此旧 deployment URL 模式需要手动添加 deployment ID 后再“一键验证”；现代 Azure v1 端点仍可同步模型。
  5. 先完全退出已经运行的 OpenCode.app，再点击“配置并启动 OpenCode”。RelayDock 使用独立的 OPENCODE_CONFIG，不会覆盖已有全局配置。
  6. 应用每天自动检查一次 GitHub Release，Updates 卡片会显示结果与时间。发现更新后，“下载并安装”会校验 digest、挂载后 App 的签名与版本，打开安装器，并在重启 RelayDock 前确认已安装版本。

Key 说明：OpenAI 需要 OpenAI Platform API Key，ChatGPT Plus/Pro 与 API 使用相互独立；Kimi Code 需要 Kimi Code Console 专用 Key，不能与 Kimi API Platform Key 混用；火山方舟 Coding Plan 需要服务商签发的 Coding Plan API Key。Kimi Code 与方舟预设会保留官方推荐的模型别名作为模型目录不可用时的兜底；若“同步模型”成功返回目录，RelayDock 会使用实际目录。Key 仅在保存端点时写入 macOS Keychain。

Cursor 一键配置

  1. 先保存并验证至少一个 OpenAI Compatible 和/或 Anthropic Endpoint。
  2. 在“Cursor 一键接入 Sub2API”中分别选择 Endpoint，点击“一键配置并打开 Cursor”。
  3. OpenAI Compatible 会写入 Cursor 的 OpenAI Key、Override Base URL 与已验证模型 ID；Anthropic 只写 Claude Key，并由本地 Bridge 将 Cursor 固定的 api.anthropic.com 目标转到所选 Endpoint。
  4. 首次 Anthropic 配置会请求一次 macOS 证书授权。证书、Bridge、Cursor 数据库事务和 Cursor 加密 Key 迁移全部验证成功后，界面才会显示成功；失败自动回滚。

Bridge 范围：只监听本机回环地址。非目标域名仍是原样加密隧道；只有 api.anthropic.com 会终止 TLS 并改写 Endpoint。请求体、响应、Prompt、Header 与 Key 均不记录。使用该路线时需要保持 RelayDock 运行。

卸载

使用 /bin/zsh 运行 Uninstall RelayDock.command。它会删除 App、Endpoint 与 Keychain API Key、OpenCode 配置、Cursor 回滚文件、Anthropic Bridge 证书/私钥/信任，以及私有本地签名 Keychain。RelayDock 不会安装根 CA，也不会修改全局系统代理。
